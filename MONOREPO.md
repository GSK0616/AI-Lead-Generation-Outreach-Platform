# LeadForge AI - Monorepo Structure\n\n## Project Organization\n\n```\nLeadForge-AI/\n├── frontend/                    # Next.js Frontend\n│   ├── src/\n│   │   ├── app/                # App Router pages\n│   │   │   ├── api/            # Frontend API calls\n│   │   │   ├── auth/\n│   │   │   ├── dashboard/\n│   │   │   ├── campaigns/\n│   │   │   ├── leads/\n│   │   │   └── page.tsx\n│   │   ├── components/         # React components\n│   │   │   ├── auth/\n│   │   │   ├── dashboard/\n│   │   │   ├── campaigns/\n│   │   │   ├── leads/\n│   │   │   ├── ui/\n│   │   │   └── layout/\n│   │   ├── hooks/              # Custom React hooks\n│   │   ├── utils/              # Frontend utilities\n│   │   └── styles/             # Global styles\n│   ├── public/\n│   ├── package.json\n│   ├── next.config.js\n│   ├── tailwind.config.ts\n│   ├── tsconfig.json\n│   └── .eslintrc.json\n│\n├── backend/                     # Express.js Backend\n│   ├── src/\n│   │   ├── api/                # API routes/controllers\n│   │   │   ├── auth.ts\n│   │   │   ├── leads.ts\n│   │   │   ├── campaigns.ts\n│   │   │   ├── ai.ts\n│   │   │   ├── billing.ts\n│   │   │   └── analytics.ts\n│   │   ├── services/           # Business logic\n│   │   │   ├── emailService.ts\n│   │   │   ├── aiService.ts\n│   │   │   ├── stripeService.ts\n│   │   │   ├── linkedinService.ts\n│   │   │   └── cacheService.ts\n│   │   ├── middlewares/        # Express middlewares\n│   │   │   ├── auth.ts\n│   │   │   ├── errorHandler.ts\n│   │   │   └── rateLimiter.ts\n│   │   ├── database/           # Database setup\n│   │   │   ├── client.ts\n│   │   │   ├── migrations/\n│   │   │   └── schema.ts\n│   │   ├── jobs/               # Bull job queues\n│   │   │   ├── emailQueue.ts\n│   │   │   ├── analyticsQueue.ts\n│   │   │   └── campaignQueue.ts\n│   │   ├── utils/              # Backend utilities\n│   │   ├── types/              # Shared code\n│   ├── types/                  # Common TypeScript types\n│   │   ├── index.ts\n│   │   ├── lead.ts\n│   │   ├── campaign.ts\n│   │   └── user.ts\n│   ├── constants/              # Shared constants\n│   │   ├── index.ts\n│   │   ├── api.ts\n│   │   └── config.ts\n│   ├── utils/                  # Shared utilities\n│   │   ├── validation.ts\n│   │   ├── formatting.ts\n│   │   └── helpers.ts\n│   └── package.json\n│\n├── docker-compose.yml          # Docker setup\n├── .env.example               # Environment template\n├── .gitignore\n├── README.md\n└── package.json (root)\n```\n\n## Folder Descriptions\n\n### Frontend (`/frontend`)\n- **Technology**: Next.js 14, React, TypeScript, TailwindCSS\n- **Responsibility**: UI, routing, client-side logic\n- **Deploy to**: Vercel\n- **Port**: 3000\n\n### Backend (`/backend`)\n- **Technology**: Node.js, Express, TypeScript\n- **Responsibility**: API endpoints, database, business logic, integrations\n- **Deploy to**: Railway/Render\n- **Port**: 5000\n\n### Shared (`/shared`)\n- **Technology**: TypeScript\n- **Responsibility**: Types, constants, utilities used by both frontend and backend\n- **Imported by**: Both frontend and backend\n\n## Setup Instructions\n\n### 1. Install Dependencies\n```bash\n# Root dependencies\nnpm install\n\n# Frontend\ncd frontend\nnpm install\n\n# Backend\ncd backend\nnpm install\n\n# Shared\ncd shared\nnpm install\n```\n\n### 2. Environment Setup\n```bash\ncp .env.example .env.local\n# Fill in all API keys\n```\n\n### 3. Run Development\n```bash\n# Option 1: Using Docker Compose\ndocker-compose up\n\n# Option 2: Separate terminals\n# Terminal 1 - Frontend\ncd frontend && npm run dev\n\n# Terminal 2 - Backend\ncd backend && npm run dev\n\n# Terminal 3 - Redis\nredis-server\n```\n\n## Development Workflow\n\n### Making API Changes\n1. Define type in `shared/types/`\n2. Implement API in `backend/src/api/`\n3. Call API from `frontend/src/hooks/`\n\n### Adding Features\n1. Create component in `frontend/src/components/`\n2. Add API route in `backend/src/api/`\n3. Add service in `backend/src/services/`\n4. Share types in `shared/types/`\n\n## Deployment\n\n### Frontend\n```bash\ncd frontend\nvercel deploy --prod\n```\n\n### Backend\n```bash\ncd backend\n# Using Railway\nrailway deploy\n\n# Or Docker\ndocker build -t leadforge-backend .\ndocker run -p 5000:5000 leadforge-backend\n```\n\n## Benefits of This Structure\n\n✅ **Separation of Concerns**: Clear boundaries between frontend and backend\n✅ **Team Scalability**: Different teams can work independently\n✅ **Independent Deployment**: Deploy frontend and backend separately\n✅ **Code Reusability**: Shared types prevent duplication\n✅ **Testing**: Each service can be tested independently\n✅ **Production Ready**: Industry-standard monorepo pattern\n✅ **Easy Migration**: Can split into separate repos later if needed\n✅ **Better Maintenance**: Clear folder structure for onboarding\n\n## Git Workflow\n\n```bash\n# Create feature branch\ngit checkout -b feature/new-feature\n\n# Work on both frontend and backend\ncd frontend\n# ... make changes\ncd ../backend\n# ... make changes\n\n# Commit\ngit add .\ngit commit -m \"feat: add new feature\"\n\n# Push\ngit push origin feature/new-feature\n```\n\n## Next Steps\n\n1. Move existing frontend code to `/frontend`\n2. Move existing backend code to `/backend`\n3. Create shared types in `/shared/types`\n4. Update imports across both services\n5. Test both frontend and backend\n6. Deploy to production\n\nThis structure is ready for scaling! 🚀\n"
